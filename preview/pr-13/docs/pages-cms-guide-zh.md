# Duan Lab｜Pages CMS 中文操作手册

本手册面向实验室负责人。日常文字、成员资料和图片可在 CMS 修改；GitHub 仓库、账号权限、构建与部署维护由网站管理员负责，不需要负责人操作代码。

## 1. 登录与选择网站

打开 https://app.pagescms.org/ ，点击 **Sign in with GitHub**，使用管理员已授权的 GitHub 账号登录。选择 **Nameme2004 / lab-website-template**。若看不到仓库或提示需要额外权限，请联系管理员，不要自行扩大权限。

## 2. 确认正式分支

在仓库的分支选择器中确认显示 **main**，再开始正式编辑。main 是正式站内容；其他分支通常是审核或预览版本。管理员应在上线时替负责人检查一次分支和编辑权限。

**当前演示期间**：PR #13 尚未合并，完整演示内容在 **codex/group-meeting-demo**。选这个分支时，Save 更新的是 [PR 预览](https://nameme2004.github.io/lab-website-template/preview/pr-13/)，不会更新正式站。管理员批准上线后，日常编辑切回 main。

## 3. 编辑英文与中文

英文和中文分别填写，不会自动翻译。带“中文”或 `zh` 的字段用于中文显示；EN / 中文按钮切换访客看到的语言。中文留空时回退英文。网站会记住上次选择的语言，检查保存效果时要选对语言。

文本编辑器支持段落、列表、加粗和链接。页面文字尽量使用这些基本格式；不要粘贴脚本、复杂 HTML 或带特殊样式的网页。

## 4. Home 与 Research

- **Home — About Us**：编辑实验室介绍、首页研究预览介绍，各有英文和中文字段。
- **Research — directions and homepage previews**：编辑页面介绍及每个研究方向的标题、完整介绍、首页摘要。数字越小越靠前；“Show on homepage”决定是否显示在首页。
- **confirmed / Confirmed by lab lead** 是公开确认状态，不能为了让提示消失而勾选。拟开展方向不能写成已经完成的课题；改变确认状态需负责人明确审核。
- 页眉和首页副标题由管理员维护，当前为“类器官疾病建模与治疗策略研究”；修改时请让管理员同步英文。

## 5. 团队成员与照片

在 **Team members** 打开成员资料，编辑姓名、职位说明、单位、个人简介及对应中文字段。新增成员时点击 **New / Add**，填写英文姓名和 Position，并保存；具体按钮名称以当前界面为准。

- **Portrait** 可选择或上传已获授权的照片，上传目录由管理员配置；无需手工输入图片路径。
- **显示在网站** 关闭时，资料暂不公开。已有示例成员保持关闭，不能把模板成员误当作真实成员重新发布。
- Position 是固定角色类别，不要用中文替换内部角色代码；中文职位写在“职位说明 — 中文内容”。
- Author name aliases 用于关联论文，请保留已确认的作者别名。
- Profile links 只填公开且获授权的信息；不要填个人隐私邮箱、电话或私人账号。
- 不随意更改已有成员英文姓名、文件名或删除成员；需要隐藏资料时关闭“显示在网站”，需要改 URL 时联系管理员。

**Team Page — 团队页面** 用于编辑团队页面介绍和照片说明。团队合影的排版、增加相册入口由管理员处理。

## 6. 论文、招聘与联系信息

### 论文

**Publications Page** 编辑页面介绍和“Selected Publications — displayed section heading”的中英文标题。演示版只显示一个“负责人代表性论文”栏目。“Legacy section heading”是保留的旧字段，不再显示，无需修改。

**Publication Sources** 用于论文来源及中英文说明。原始论文题目、作者、期刊不能为了翻译而改写；中文解释写入“论文说明 — 中文内容”。上传授权图片后，论文卡片才显示封面；没有图片时只显示文献信息。

新增论文时请先请管理员核对 DOI、完整作者和正式发表状态。论文来源记录还需要加入 Publications Page 的 **Displayed publication IDs** 才会进入当前栏目；可将核实后的标识原样复制，拿不准时让管理员完成。不要直接修改自动生成的 citations 文件。负责人既往合作成果与新实验室成果应在介绍中明确区分；在审稿件不能写成已发表。

### 招聘与联系方式

**Join Us** 编辑页面介绍、申请说明及对应中文。“Positions”条目的 status、confirmed、截止日期只按负责人确认的信息填写；不要自行宣布名额、开放申请或录取承诺。尚未确定时保留当前状态。

**Contact** 编辑公开联系信息与中英文说明。confirmed 涉及公开展示控制，不能随意切换。当前演示中的邮箱、地址注明来自官方教师主页，实验室具体安排尚待确认。只使用已授权公开的联系信息。

## 7. Save 后检查网站

1. 编辑前先记住或复制需要修改的原文，尤其是列表和非空字段。
2. 点击 **Save**，等界面完成保存，不要立刻关闭页面。
3. 重新打开同一条记录，确认中英文、列表、链接、确认状态和已有内容都还在。
4. 等待网站自动构建并部署，通常需要几分钟。Save 成功不代表网站已经发布完成。
5. 正式 main 的内容检查 [正式网站](https://nameme2004.github.io/lab-website-template/)；演示分支检查 [PR #13 预览](https://nameme2004.github.io/lab-website-template/preview/pr-13/)。选择相应语言，再刷新确认。

## 8. 保存后没有变化

依次检查：

1. CMS 是否选对分支：正式是 main，演示是 codex/group-meeting-demo。
2. 打开的地址是否对应这个分支，而不是另一个版本。
3. 修改的是英文还是中文，网站是否切到对应语言。
4. 重新打开 CMS 记录，修改是否仍存在；若不存在，说明未成功保存。
5. 等几分钟后再刷新；仍不变，可用 Ctrl+F5，或换无痕窗口打开。
6. 如果仍有问题，把页面名称、保存时间、分支和截图发给管理员，由管理员检查 [GitHub Actions](https://github.com/Nameme2004/lab-website-template/actions)。不必自行处理构建错误。

## 9. 避免数据丢失和隐私误公开

- 一次只改必要字段，不清空无关英文、中文、链接和列表。
- 不点击删除整个成员、论文、研究方向或招聘条目；暂不公开可使用相应展示状态，并请管理员确认。
- 空的可选字段可能在保存后不再列出，这是正常的；**原先非空的内容必须仍保留**。
- 编辑列表后逐项核对数量、顺序、作者别名、链接和确认状态。
- 同一页面避免两个人同时编辑；保存前重新打开过期页面，避免覆盖别人刚保存的修改。
- 如果非空数据消失，立即停止再次保存并联系管理员。管理员可从 GitHub 历史恢复，不需要负责人学习 Git。
- 不上传简历、私人联系方式、未公开研究数据、未授权照片或保密稿件。

管理员负责最后审核事实、权限与部署；CMS 方便日常编辑，不能替代科研与招聘信息审核。
